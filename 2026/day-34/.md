Day 34 – Docker Compose Advanced
Task 1: 3-Service App Stack

docker-compose.yml:

services:
  web:
    build: ./app
    ports:
      - "5000:5000"
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started

  db:
    image: postgres:16
    environment:
      POSTGRES_DB: appdb
      POSTGRES_USER: user
      POSTGRES_PASSWORD: secret
    volumes:
      - db_data:/var/lib/postgresql/data

  redis:
    image: redis:alpine

volumes:
  db_data:

Dockerfile:

FROM python:3.12-slim
WORKDIR /app
COPY . .
RUN pip install flask psycopg2-binary redis
CMD ["python", "app.py"]
Task 2: depends_on & Healthcheck
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U user -d appdb"]
  interval: 5s
  timeout: 5s
  retries: 5
depends_on:
  db:
    condition: service_healthy

The web app waits until PostgreSQL is healthy, not merely running.

Task 3: Restart Policies
restart: always
always → Restarts the container whenever it stops.
on-failure → Restarts only when the container exits with an error.
Use always for important services such as databases; use on-failure for workloads where restarting after failures makes sense.
Task 4: Custom Dockerfile
web:
  build: ./app

Build and restart:

docker compose up -d --build

This rebuilds the image after code/Dockerfile changes.

Task 6: Scaling
docker compose up -d --scale web=3

Scaling can fail if all replicas try to bind the same host port (5000:5000).

A single host port cannot normally be mapped to multiple containers simultaneously.

Key takeaway: Docker Compose can manage complete application stacks with multiple services, healthchecks, persistent volumes, networks, restart policies, and scaling.
